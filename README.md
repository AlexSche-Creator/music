# Музыкальный тренажёр (PWA)

Личный тренажёр гитариста: ступени, аккорды, чувства, прогрессии. Две тональности — **C major** и **A minor**. Полностью статический сайт, без бэкенда, разворачивается на GitHub Pages, ставится на iPhone как PWA, работает офлайн.

## Что внутри

- 6 базовых режимов тренировки + ещё 3:
  - Ступень → аккорд
  - Аккорд → ступень
  - Чувство → аккорд
  - Аккорд → чувство
  - На слух: аккорд → ступень
  - На слух: аккорд → чувство
  - Угадай следующий аккорд (по прогрессиям)
  - Карточки (flashcards)
  - Экзамен (20 вопросов, без подсказок)
  - «Все ступени подряд» и «Сравнить тональности» как обзорные экраны
- Аудио на WebAudio API: piano-like (аддитивный) и plucked / гитарный. Без сэмплов, грузится мгновенно.
- IndexedDB-хранилище ответов и сессий (с fallback в localStorage).
- Weighted-repetition алгоритм: чаще возвращает ошибки, поднимает забытое, не повторяет 10 раз подряд одно и то же.
- Полная статистика: точность, серия, heatmap, accuracy по режимам, hardest/strongest items, среднее время реакции.
- Напоминания (учитывая ограничения iOS — см. ниже).
- Тёмная тема, чёрный / белый / Tiffany. iPhone-first.
- Юнит-тесты на `theory`, `stats` и `scheduler`.

## Запуск локально

В корне репозитория:

```bash
python3 -m http.server 8765
```

Открой [http://localhost:8765/](http://localhost:8765/) либо `http://<ip-компьютера>:8765/` с iPhone в той же Wi-Fi-сети.

Сборка не нужна — это чистый ES-модульный код без бандлера. Иконки PWA можно перегенерировать через:

```bash
python3 icons/generate.py
```

## Тесты

```bash
node tests/theory.test.mjs
node tests/stats.test.mjs
node tests/scheduler.test.mjs
```

## Деплой на GitHub Pages

1. Зайди в **Settings → Pages** в репозитории `music`.
2. Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Дождись зелёного статуса.
4. Приложение будет доступно по `https://<user>.github.io/music/` — открывается сразу, без подпапки.

PNG-иконки PWA генерируются автоматически через GitHub Actions (`.github/workflows/icons.yml`) — при первом пуше в `main` экшен запускает `icons/generate.py` и докладывает иконки в репозиторий.

## Установка на iPhone как PWA

1. Открой `https://<user>.github.io/music/` в **Safari** на iPhone.
2. Нажми кнопку «Поделиться» → **«На экран „Домой"»** → «Добавить».
3. Запускай иконку с домашнего экрана — это и есть «установленное» приложение.
4. Появятся системные права: при первой попытке включить уведомления Safari покажет диалог.

Поддержка ставится автоматически: на iOS 16.4+ работает Web Push в установленных PWA. До установки — уведомления недоступны.

## Уведомления и напоминания

На iPhone есть существенные ограничения, которые тренажёр обходит так:

| Сценарий | Что делает приложение |
| --- | --- |
| PWA установлена, разрешение дано, вкладка активна | Реальное уведомление через Service Worker (`showNotification`). |
| PWA установлена, вкладка закрыта | iOS Safari в фоне таймер не выполнит → пропуск. См. .ics ниже. |
| PWA не установлена | API уведомлений недоступен. См. .ics или Apple Shortcuts. |
| Любой случай | Кнопка «Скачать .ics для Календаря» — Apple Calendar пришлёт нативное напоминание. |
| Любой случай | Внутренняя плашка «время потренироваться» при первом открытии. |

Все эти варианты честно описаны в экране **Настройки**.

### Включить уведомления

1. Открой `Настройки` → блок «Напоминания».
2. Кнопка «Запросить уведомления». Safari покажет системный диалог.
3. После «Разрешить» в Настройках iOS можно дополнительно настроить стиль уведомлений.

### Если нужны жёсткие напоминания

Используй кнопку **«Скачать .ics для Календаря»** — она кладёт в Apple Calendar повторяющееся событие с алармом. iOS-уведомление сработает гарантированно, даже без открытого тренажёра.

### Поток данных

```
вопрос  ─►  scheduler.pickNext (по весам)
       ─►  training.renderQuestion
ответ  ─►  store.logAnswer (IDB)
       ─►  scheduler.recordOutcome (EMA)
сессия ─►  store.finishSession
статы  ─►  stats.summarize / perDay / heatmap / hardestByField
```

## Что протестировано

- `theory.js`: парсинг аккордов, MIDI-ноты, ступень↔аккорд, генерация опций, угадывание следующего аккорда.
- `stats.js`: точность, perDay, streak, heatmap, hardest/strongest, by-mode, средняя длительность сессии.
- `scheduler.js`: EMA, weighted pick, anti-repeat, hardestItems, improvedItems.
- Smoke-test статики: все ресурсы отдаются HTTP 200.

## Ограничения iPhone / iOS Safari

| Ограничение | Как обходим |
| --- | --- |
| Web Push только в установленных PWA | Подсказка в Settings + .ics fallback. |
| Уведомления в фоне без Push невозможны | Используется setTimeout, пока вкладка жива; для фона — .ics. |
| Periodic Background Sync недоступен | Не используем. |
| IDB может очиститься после 7 дней «бездействия» | Кнопка «Экспорт JSON». |
| AudioContext требует user-gesture | Контекст создаётся лениво на первом нажатии. |

## Спорные решения

1. **Без бандлера / без Vite.** Чистые ES-модули и importmap-free код — это даёт мгновенный загрузочный путь и тривиальный деплой. Если приложение разрастётся (Tone.js, графики на canvas), миграция на Vite займёт час.
2. **WebAudio вместо Tone.js / сэмплов.** Сэмплированное пианино звучит лучше, но добавляет 1–3 МБ ассетов. Тренажёру важнее быстрый отклик и офлайн.
3. **Один большой `training.js`.** Все 9 режимов делят один UI-конвейер, чтобы переключение между ними было бесшовным. Альтернатива — модуль на каждый режим — давала бы 9 почти одинаковых файлов.
4. **Hash-router вместо History API.** Hash-маршруты ломаются меньше при размещении в подпапке GitHub Pages.
5. **Feelings хранятся per-tonality.** Один и тот же аккорд (например C) играет разную функциональную роль в C major и в A minor, поэтому ассоциации логично различать.
6. **PNG-иконки генерируются в CI.** Бинарники не любят ручных коммитов; SVG и generate.py в репо дают воспроизводимый источник, экшен докладывает PNG.
